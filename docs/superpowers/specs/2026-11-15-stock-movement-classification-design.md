# 出入库业务分类与颜色设计

## 背景与目标

库存管理同时覆盖线下门店与线上商城。当前入库/出库单据的类型过于粗略，例如所有销售出库都显示为「销售出库」，不能从列表快速区分线上商城订单和线下门店销售。本次需要清晰表达业务场景，并为不同场景提供有辨识度的颜色。

## 分类模型

单据保留「业务类型」和「业务来源」两个维度。业务类型描述库存变动原因，业务来源描述关联渠道或往来方。列表及详情中将二者组合成可读的场景名称，筛选按完整场景进行。

| 方向 | 业务类型 | 来源 | 展示名称 |
| --- | --- | --- | --- |
| 入库 | 采购入库 | 供应商 | 采购入库 |
| 入库 | 退货入库 | 线上商城 | 线上商城退货入库 |
| 入库 | 退货入库 | 线下门店 | 线下门店退货入库 |
| 入库 | 盘盈入库 | 库存调整 | 盘盈入库 |
| 出库 | 销售出库 | 线上商城 | 线上商城销售出库 |
| 出库 | 销售出库 | 线下门店 | 线下门店销售出库 |
| 出库 | 采购退货出库 | 供应商 | 采购退货出库 |
| 出库 | 报损出库 | 库存调整 | 报损出库 |

## 颜色映射

每个具体场景使用独立颜色标签；颜色只用于识别单据场景，不改变库存增减逻辑。

| 展示场景 | 建议颜色 |
| --- | --- |
| 采购入库 | 蓝色 |
| 线上商城退货入库 | 青绿色 |
| 线下门店退货入库 | 翠绿色 |
| 盘盈入库 | 青色 |
| 线上商城销售出库 | 紫色 |
| 线下门店销售出库 | 橙色 |
| 采购退货出库 | 琥珀色 |
| 报损出库 | 红色 |

颜色标签需要保持足够的文字对比度，并在列表、建单类型选择、单据详情中使用同一映射。入库/出库方向仍由页面方向和提示图标表示。

## 页面行为

- 入库管理和出库管理仍各自维护，只展示与该方向兼容的业务类型和来源组合。
- 建单时先选业务类型。销售出库、退货入库需要再选业务来源（线上商城/线下门店）；采购、采购退货、盘盈、报损的来源固定，不要求重复选择。
- 类型筛选显示全部具体场景。选中「线上商城销售出库」等选项时，仅展示对应类型与来源组合。
- 列表、详情、CSV 导出使用相同的场景名称；CSV 同时保留业务类型与业务来源列，便于下游分析。
- 往来单位输入标签和提示随场景调整：采购相关指向供应商；商城相关指向订单；门店销售/退货指向门店或单据；盘盈/报损为内部调整说明。
- 现有单据数据需要补全来源。历史「销售出库」根据已有往来单位/备注识别渠道；无法判断时采用明确的「待确认来源」展示，不静默误标成线下门店。

## 范围边界

- 本次不实现仓库调拨。调拨必须把调出仓与调入仓关联为一笔完整业务，并保障两个仓库库存同步更新；它不是单仓入/出库类型标签可以完整表达的流程。
- 不改动单据确认、作废、库存校验或库存持久化策略，只调整分类表达、来源字段、颜色和相关筛选/导出。

## 验收标准

1. 入库、出库列表的类型标签按具体业务场景显示不同颜色，列表/详情颜色一致。
2. 可以分别创建线上商城和线下门店的销售出库、退货入库。
3. 类型筛选可以精确筛出一个业务场景。
4. 导出数据包含业务类型、业务来源和清晰的组合展示名称。
5. 既有采购、采购退货、盘盈、报损单据仍可正常筛选、查看和建单，库存方向校验行为不变。
6. 模糊来源的旧单据不会被错误地归入线上或线下。
