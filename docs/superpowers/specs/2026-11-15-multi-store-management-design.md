# 多门店管理与权限体系设计

## 背景与目标

当前门店管理系统按单门店演示态运行。人员、诊室和排班使用页面内的模拟数据，登录态不包含用户身份、角色或门店范围。随着门店数量增加，需要建立统一的门店主数据、门店工作区、账号角色和跨门店数据隔离规则。

本设计覆盖以下目标：

1. 支持超级管理员创建和管理多家门店，并从全局视角查看门店经营概况。
2. 人员、诊室、排班及业务数据明确归属门店。
3. 店长、店员、视光师登录后只能访问所属门店；开发者和超级管理员拥有全局范围。
4. 支持一座仓库关联多家门店，所有关联门店共用仓库的实际库存池。
5. 增加独立的系统管理模块，统一管理权限、用户、系统设置和日志。

## 设计原则

- **全局视角与单店工作区分离：** 全局总览用于经营比较；具体业务在明确的门店上下文中操作。
- **账号权限与人员岗位分离：** 系统角色控制操作权限，员工档案中的职称/岗位描述专业信息。
- **数据范围由服务端强制执行：** 菜单隐藏不构成权限控制；查询、写入、导出和统计都校验门店范围。
- **共享库存不复制：** 库存数量只归属仓库；门店通过显式关联获得共享库存的可见与使用范围。
- **保留历史数据：** 门店停用或人员离职不物理删除已有业务记录。

## 信息架构

```text
开发者 / 超级管理员
├── 全门店总览
├── 门店管理
│   ├── 门店列表
│   ├── 新建门店
│   └── 单店工作区
│       ├── 门店概况
│       ├── 人员管理
│       ├── 诊室管理
│       ├── 门店排班
│       └── 仓库关联
├── CRM、库存、商城、收银等业务模块
└── 系统管理
    ├── 权限管理
    ├── 用户管理
    ├── 系统设置
    └── 日志管理

店长 / 店员 / 视光师
└── 登录后进入唯一归属门店
    ├── 本店仪表盘
    ├── 本店可用业务模块
    └── 已关联共享仓库的可用库存
```

### 全局与单店导航

- 开发者和超级管理员登录后进入「全门店总览」，可按门店查看核心指标和状态。
- 全局用户通过门店列表进入指定门店工作区。顶部持续显示当前门店名称，并提供返回全门店总览的入口。
- 店长、店员、视光师登录后直接进入所属门店，不显示全门店列表或门店切换器。
- 现有 CRM、库存、商城、收银等模块保留；在单店上下文中按角色权限展示，并只访问本店数据及明确授权的共享仓库存。
- 系统管理为全局独立模块，不挂在任一门店工作区之下。

### 全门店总览

首期提供跨门店汇总和门店比较，不直接呈现患者级明细。建议指标如下：

| 指标 | 口径 |
| --- | --- |
| 门店数量与状态 | 按启用、停用等门店状态汇总 |
| 销售额 | 已支付金额扣除成功退款金额 |
| 订单量 | 已支付且未取消的订单数 |
| 新增客户 | 在所选门店首次建立档案的客户数 |
| 预约与到诊 | 按预约门店统计预约数、到诊数及到诊率 |
| 库存预警 | 汇总关联仓库中的低库存和临期预警数量 |

总览支持时间范围和门店筛选/对比。点击门店后进入其工作区，再查看单店业务明细。全局库存预警按唯一的「仓库 + SKU」组合去重；门店对比中，共享仓预警会显示在每个关联门店下。具体预警阈值沿用库存配置，不在总览中重复维护。

## 核心数据模型

当前按单一经营主体下的多门店设计，不引入多组织/多租户隔离。

| 实体 | 关键字段与职责 |
| --- | --- |
| 门店 `Store` | 门店 ID、名称、编码、地址、联系方式、营业信息、状态 |
| 系统账号 `User` | 账号 ID、登录凭证、角色、状态；本地账号必须绑定一个门店，全局角色不绑定门店 |
| 员工档案 `StaffProfile` | 门店 ID、姓名、职称/岗位、擅长描述、入离职状态；可选关联一个系统账号 |
| 仓库 `Warehouse` | 仓库 ID、名称、地址、状态；库存数量的唯一归属单元 |
| 门店仓库关联 `StoreWarehouse` | 门店 ID、仓库 ID、关联状态、该门店的默认出库仓标记 |
| 门店业务记录 | CRM、预约、诊室、排班、收银、门店订单及门店发起的库存流水均保存门店 ID |
| 仓库库存 | 按 SKU 和仓库 ID 保存可用数量，不为每家关联门店复制库存余额 |

### 人员档案与账号

- 员工档案服务于人员管理、排班和门店业务；系统账号服务于登录鉴权和操作审计。
- 员工档案可以没有系统账号；被授权登录的员工通过账号关联到档案。
- 「医生、前台、视训师」等现有信息保留为职称/岗位字段，不自动创建新的权限角色。
- 一个本地账号只属于一家门店。开发者和超级管理员为全局账号，不绑定单一门店。

## 门店与仓库关联

门店和仓库为多对多关系：一家门店可以关联多个仓库，一个共享仓库也可以关联多家门店。关联关系中可为每家门店分别设置默认出库仓。

### 共享库存规则

1. 所有已关联门店读取同一仓库的可用库存总量；关联多家门店不会复制或放大库存。
2. 门店产生的销售、退货等库存业务同时记录 `storeId` 和 `warehouseId`。库存流水归属发起业务的门店，但实际余额统一在仓库维度更新。
3. 门店用户只能查看本店的库存业务单据；不能查看其他关联门店的操作明细。
4. 总部采购入库、盘点调整等仓库级流水由全局库存管理员处理，仅开发者和超级管理员可以查看其完整记录。
5. 门店可查看已关联仓库的可用总量；门店销售等业务扣减共享库存前，服务端按仓库余额执行原子校验，避免并发超卖。
6. 门店销售、门店退货等由本店业务发起的库存变化必须带本店 `storeId`，只能通过授权的业务流程触发。门店不能自行创建总部采购入库或盘点调整来改变共享库存。需要补货或跨仓流转时，应通过受控的库存操作；跨仓调拨需作为同时更新调出仓和调入仓的完整单据实现。
7. 解除门店与仓库的关联前，系统需检查未完成单据和默认出库仓设置；解除关联不会删除仓库或库存。

## 角色与权限模型

采用基于角色的访问控制（RBAC），同时强制执行门店数据范围。首期只有下列 5 个内置角色，不开放自定义角色。

| 角色 | 数据范围 | 权限边界 |
| --- | --- | --- |
| 开发者 | 全系统、全部门店 | 平台最高权限，可访问系统与业务数据并处理技术维护；操作必须记录审计日志 |
| 超级管理员 | 全部门店 | 全门店总览和明细；创建/停用门店；管理账号、角色分配、全局设置和全局日志；可进入任意门店工作区 |
| 门店店长 | 唯一所属门店 | 管理本店人员档案、诊室、排班、CRM、预约和收银；创建/停用本店店员与视光师账号；查看本店操作日志及关联仓库库存；不能管理仓库主数据、总部库存调整、全局账号或系统级权限模板 |
| 店员 | 唯一所属门店 | 执行本店客户接待、预约、收银等日常操作；按业务需要查看本店关联仓库库存；不能管理人员、账号、仓库库存调整、系统设置或共享仓库配置 |
| 视光师 | 唯一所属门店 | 查看本店排班、客户档案及处理视光相关业务；按业务需要查看本店关联仓库库存；不能管理账号、仓库库存调整、价格体系或系统设置 |

### 权限管理规则

- 权限至少区分菜单访问和关键操作（查看、新增、编辑、停用、导出等）。
- 权限管理页展示角色权限矩阵；角色模板由开发者维护，超级管理员负责账号角色分配。
- 超级管理员不能把开发者或超级管理员权限授予本地账号，也不能扩大本地账号的数据范围。
- 店长只能管理本店的店员、视光师账号；不能改变账号的门店归属或提升为店长。
- 视光师岗位信息与视光师权限角色不是同一字段；只有被分配「视光师」权限角色的账号才取得该权限。

## 系统管理模块

### 权限管理

展示 5 个内置角色、菜单/操作权限和数据范围。角色权限模板受保护，不提供自定义角色创建。角色模板变更由开发者操作并记录审计日志。

### 用户管理

- 超级管理员可按姓名、账号、门店、角色和状态筛选全局账号，创建、停用账号、重置凭证和调整门店角色。
- 店长仅能查看和维护本店店员/视光师账号。
- 停用账号立即阻止新登录；历史操作和业务数据保留。
- 用户改绑门店由超级管理员执行，并要求明确确认；历史业务记录仍归属原门店，不随账号改绑迁移。

### 系统设置

- 全局配置包括登录安全、通用字典和系统集成等。
- 门店地址、联系方式、营业时间等放在门店资料中，按门店管理。
- 集成密钥等敏感配置在界面中脱敏展示，读取和修改均记录日志。

### 日志管理

- 记录登录结果、账号状态与角色变更、门店创建/停用、权限模板变化、仓库关联变化、库存操作及关键业务写入。
- 日志至少包含操作者、操作时间、动作、对象、所属门店/仓库和结果。
- 超级管理员和开发者可在系统管理中查询全局日志；店长在本店工作区查看限定为本店的操作日志，不获得全局系统日志入口。
- 日志为只追加记录，不提供编辑或删除入口。

## 数据访问与安全要求

- 每个业务请求由服务端从已验证的账号上下文取得角色和门店范围；不得信任前端传入的 `storeId`。
- 本地账号访问的查询、详情、统计、导出、搜索建议和写入均限定在所属门店。
- 超级管理员进入单店工作区后，业务操作必须显式携带当前门店上下文；全局总览中的聚合查询不得泄露患者级明细。
- 共享仓库数量仅对关联门店开放；库存流水仍按门店范围过滤。
- 权限校验覆盖 API、页面路由和后台任务。未授权访问返回无权提示并记录安全日志。
- 门店状态包括待启用、启用和停用。门店处于待启用或停用时，普通门店账号不能登录或继续写入；超级管理员仍可查看历史记录。

## 关键业务流程

### 新建门店

1. 超级管理员填写门店名称、编码和基础资料。
2. 选择一个或多个已有仓库，并为该门店指定默认出库仓。
3. 创建或指定一名门店店长账号。
4. 保存为待启用状态；确认资料和关联关系后启用门店。
5. 启用后，店长首次登录进入该门店工作区，并可维护人员档案、诊室和排班。

### 员工账号入职

1. 店长创建员工档案，填写岗位/职称等资料。
2. 如员工需要登录，再创建或关联账号并分配「店员」或「视光师」角色。
3. 账号绑定当前门店；服务端拒绝空门店或跨店绑定。
4. 离职时停用账号并将员工档案标记为离职，保留历史排班和业务记录。

### 停用门店

1. 超级管理员确认停用，并查看该门店未完成业务和仓库关联。
2. 停用后阻止本地账号登录及新业务写入。
3. 历史数据、日志和库存流水保留；恢复门店时由超级管理员重新启用。
4. 有历史数据的门店不提供物理删除，只允许停用。

## 现有数据迁移

- 将当前单门店的人员、诊室、排班、客户和已有门店业务数据归入一个默认门店。
- 现有仓库与门店的关联由超级管理员核实后建立，不根据仓库名称或城市自动推断。
- 商品主数据保持组织级共享；库存继续按仓库保存，迁移不得复制库存余额。
- 对无法确定门店归属的历史业务，迁移前提供待核对清单；确认前不静默归入任一新门店。

## 范围边界

- 首期按单一经营主体下的多门店设计，不包含多组织、多租户或加盟商层级。
- 本期只提供 5 个内置角色，不提供自定义角色、跨门店员工账号或门店级权限模板编辑。
- 共享仓库存使用同一个实际余额；不建设按门店划分库存额度/预占量的子库存模型。
- 跨仓调拨必须作为独立的双仓完整业务处理，不以普通单仓入库或出库替代。
- 开发者与超级管理员的跨门店操作都必须写入审计日志。

## 验收标准

1. 超级管理员登录后可查看全门店 KPI、门店对比和门店列表，并进入任一门店查看完整业务。
2. 超级管理员可创建、启用和停用门店；有历史数据的门店不能物理删除。
3. 店长、店员、视光师登录后自动进入唯一所属门店，不能通过修改 URL、请求参数或导出条件访问其他门店数据。
4. 人员档案、诊室、排班、客户和门店业务记录均带有明确门店归属。
5. 店长可维护本店员工档案以及店员/视光师账号，但不能创建全局账号、改变门店归属或授予全局权限。
6. 店员、视光师只能访问各自角色允许的本店业务；菜单权限与服务端操作权限一致。
7. 同一仓库关联多个门店时，各关联门店看到相同的仓库可用总量；库存余额只保存一份。
8. 门店用户只能查看本店库存业务单据，不能查看其他门店或总部库存操作流水。
9. 并发出库时服务端基于共享仓实时可用量校验，不得产生负库存。
10. 系统管理包含权限管理、用户管理、系统设置和日志管理；用户、权限、门店和库存关键操作可追溯。
11. 全局总览仅展示聚合指标；查看客户级或单据级详情必须进入具体门店工作区。
12. 现有单门店数据迁入默认门店，仓库关联由管理员确认，库存总量保持迁移前后不变。
